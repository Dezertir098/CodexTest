# Настольная программа для Windows

## Для пользователя

Откройте GitHub → Releases → последний выпуск → Assets → файл `Put-k-EGE-<версия>-x64-portable.exe`. Это переносная программа для Windows 10/11 x64; установка Node.js и браузера не требуется. После запуска появится отдельное окно. Порт 5173 и сервер не используются.

Сборка не подписана коммерческим сертификатом. Windows может сообщить о неизвестном издателе. Не отключайте защиту системы целиком; при необходимости сначала сверьте хеш с SHA256SUMS.txt из того же выпуска.

Данные хранятся в `%APPDATA%\PutKEGE`, а не рядом с EXE. Замена EXE новой версией не удаляет прогресс. Для резервной копии и переноса на другой компьютер используйте «Настройки → Экспорт / Импорт». Уже накопленный браузерный прогресс автоматически в настольную программу не переносится: экспортируйте JSON в браузере и импортируйте в программе.

Обучение работает без интернета. Внешние ссылки на ФИПИ открываются системным браузером только по нажатию. ИИ-наставник не включён в настольную версию; при попытке запроса отображается сообщение, локальные объяснения остаются доступны. Автоматических обновлений нет — новая версия скачивается из Releases.

## Для разработчика

```bash
npm ci
npm run desktop          # production-сборка интерфейса и запуск Electron
npm run desktop:test     # проверка границ доступа к ресурсам и внешних URL
npm run desktop:smoke    # реальное окно: офлайн-урок, маршруты, сохранение после перезапуска
npm run desktop:pack:win # release/Put-k-EGE-<версия>-x64-portable.exe
```

Предпочтительная сборочная платформа — Windows с Node.js 24. На Linux возможна кросс-сборка, но это не проверка запуска Windows-программы. `npm run desktop:smoke -- --packaged` выполняется на Windows и проверяет именно упакованный `release/win-unpacked/Put-k-EGE.exe`. Тест использует временный профиль, который затем удаляет; пользовательский прогресс не затрагивается.

На Linux тест использует headless Ozone и `--no-sandbox` только как флаг тестового процесса в изолированной облачной среде. Обычная программа не передаёт этот флаг, рендерер запускается с `sandbox: true`, `contextIsolation: true`, `nodeIntegration: false`. Если текущая сборка Electron не поддерживает headless Ozone, тест следует запускать в графической сессии; задайте `PUTKEGE_TEST_GUI=1`.

Electron 45 загружает runtime по требованию. Если команда `electron .` ещё не выполнялась, для явной установки выполните `npx install-electron --no`. В средах с HTTP(S)-прокси Node.js 24 поддерживает `NODE_USE_ENV_PROXY=1`; настройки проверки TLS и SHA256 не отключаются.

### Автоматический выпуск на GitHub

Workflow `.github/workflows/windows-desktop.yml` на Windows:

1. Устанавливает зависимости строго по lock-файлу, выполняет тесты.
2. Собирает EXE и запускает реальную упакованную программу.
3. Проверяет офлайн-урок, навигацию и черновик после полного перезапуска.
4. Загружает EXE и SHA256 как артефакт Actions.
5. Для тега `v*` создаёт GitHub Release с теми же файлами. Если тесты не прошли, публикации нет.

Перед новым выпуском обновите `version` в package.json/lock-файле и заметки `docs/windows-release.md`, создайте соответствующий тег и отправьте его. Ручной запуск workflow создаёт артефакт Actions без публикации выпуска. Сам факт отправки тега не подтверждает успешную сборку — проверяйте статус Actions.

### Как устроена оболочка

`desktop/main.cjs` — процесс Electron без сторонних серверов. Упакованный `dist/` обслуживается через собственную защищённую схему `study://app`; это обеспечивает постоянный origin localStorage независимо от временной папки переносного EXE. Маршруты в настольной версии используют HashRouter; браузерная версия сохраняет BrowserRouter. Vite собирает относительные пути к ресурсам.

`desktop/security.cjs` ограничивает доступ каталогом `dist/`. Не разрешены произвольные файлы, веб-вью и разрешения камеры/микрофона; внешние HTTP(S)-ссылки открываются в системном браузере. Программа не предоставляет рендереру Node.js или API файловой системы. Ключей и серверного ИИ в установочный файл не включается.
